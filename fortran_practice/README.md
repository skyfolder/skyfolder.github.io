# Fortran 2장 실습 채점기

브라우저만으로 도는 정적 페이지입니다. 서버도 빌드 도구도 필요 없습니다.
2장 「프로그램 구조와 기본 문법」의 본문 예제·문제은행·보충 예제를 실습 문제 50개로 옮겼습니다.

| 구분 | 문항 | 출처 |
|---|---|---|
| 복습 | 1–18 | 수업 본문 예제 (chapter02) |
| 이론 | 19–38 | 출제 예상 문제은행 20문제 |
| 실습 | 39–50 | 절별 보충 예제 (2.1-1 ~ 2.4-2) |

답은 모두 한 줄 입력으로 끝납니다. 50번만 두 줄입니다.

## 파일 구성

```
index.html                  화면 + 채점
normalize.js                채점 규칙과 SHA-256   ← index.html, build.html 이 공유
problems.js                 문제 본문 (정답 없음)
answer/
  answers.js                정답 지문 + 가려 둔 해설   ← 배포됨
  answers.source.js         평문 정답 (강사용)         ← 배포 금지
  build.html                정답 파일 재생성 도구       ← 배포 금지
.gitignore                  위 두 파일을 커밋에서 제외
```

## GitHub Pages에 올리기

1. 저장소를 만들고 파일을 루트에 올립니다. `.gitignore` 가 평문 정답과 강사용 도구를 자동으로 빼 줍니다.
2. 올린 뒤 저장소 웹 화면에서 `answer/` 안에 `answers.js` 하나만 있는지 눈으로 확인하세요.
3. Settings → Pages → Source를 `Deploy from a branch`, 브랜치를 `main` / `root` 로 지정합니다.
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/` 으로 접속합니다.

로컬에서는 `index.html` 을 더블클릭하면 그대로 열립니다.

## 정답이 새지 않게 한 방법

`answer/answers.js` 에는 평문 정답이 없습니다. 정답을 채점 규칙대로 정규화한 뒤 소금값을 섞어 구한 SHA-256 지문만 들어 있습니다. 채점은 학생이 입력한 답을 같은 방식으로 지문화해 비교하는 방식이라, 정답 원문 없이도 맞고 틀림을 가릴 수 있습니다. 해설도 base64로 가려 두어 파일을 열어봐도 바로 읽히지 않습니다.

**다만 정직하게 말하면, 정적 페이지에서 완벽한 차단은 불가능합니다.** 채점 코드가 브라우저에 그대로 내려가므로, 마음먹은 학생은 후보 답을 넣어보며 지문을 맞춰볼 수 있습니다. 보기가 넷뿐인 객관식은 특히 그렇습니다. 이 방식이 막아 주는 것은 "파일을 열어 정답을 그냥 읽는 일"이고, 성적에 반영되는 시험이라면 채점을 서버에서 해야 합니다.

`base64`는 암호가 아니라 가림막입니다. 이 점을 감안해 해설을 쓰세요.

## 문제나 정답을 고칠 때

문제 본문은 `problems.js`, 정답과 해설은 `answer/answers.source.js` 에 있습니다. **둘 다 `id` 로 짝지어집니다.**

정답을 고쳤다면 반드시 해시를 다시 만들어야 합니다.

1. `answer/build.html` 을 브라우저로 엽니다.
2. **생성하기** → **파일로 저장** 을 누릅니다.
3. 내려받은 `answers.js` 로 `answer/answers.js` 를 덮어씁니다.

`normalize.js` 의 채점 규칙이나 소금값(`SALT`)을 바꿨을 때도 똑같이 다시 만들어야 합니다. 안 그러면 모든 문제가 오답 처리됩니다.

새 문제를 추가하려면 두 파일에 같은 `id` 로 항목을 넣습니다.

```js
// problems.js
{ id: 51, section: "practice", topic: "2.5 입출력", type: "line",
  title: "표준 입력 받기",
  question: "정수 <code>n</code> 을 키보드에서 읽어 들이는 문장을 한 줄로 쓰시오.",
  hint: "출력이 print 라면 입력은 무엇일까." }

// answer/answers.source.js
51: { answers: ["read *, n"],
      explanation: "read *, n 이다. 별표는 형식을 컴파일러에 맡긴다는 뜻이다." }
```

`type` 은 네 가지입니다.

- `line` — 한 줄 코드. Fortran 규칙으로 느슨하게 비교합니다.
- `code` — 여러 줄 코드. 비교 규칙은 `line` 과 같고 입력 상자만 커집니다.
- `text` — 숫자, 기호, 명령어처럼 코드가 아닌 답.
- `choice` — 객관식. `options` 배열을 주고 정답에는 보기 번호(0부터)를 문자열로 적습니다.

## 채점 기준

Fortran 문법의 관용을 반영해 아래 차이는 정답으로 인정합니다.

| 무시하는 것 | 예 |
|---|---|
| 대소문자 | `PRINT` = `print` |
| 들여쓰기·여분 공백 | `a  =  1` = `a=1` |
| 구두점 주변 공백 | `mod( n, 2 )` = `mod(n,2)` |
| 주석과 빈 줄 | `! 설명` 이하 삭제 |
| end 문 표기 | `end program hello` = `endprogram` |
| 관계 연산자 표기 | `.eq.` = `==`, `.ge.` = `>=` |
| 따옴표 종류 | `"abc"` = `'abc'` |
| 줄 연결 기호 | `&` 로 이어진 줄을 한 줄로 |

문자열 안의 내용은 대소문자까지 그대로 비교합니다. 출력 결과가 달라지기 때문입니다.

틀렸을 때는 "채점기가 읽은 내 답"으로 정규화 결과를 보여 주므로, 학생이 왜 틀렸는지 추측하지 않아도 됩니다. 두 번 틀리면 힌트가 자동으로 펼쳐집니다.

## 알아두면 좋은 점

- 진행 상황은 새로고침하면 초기화됩니다. 유지하려면 `index.html` 의 `state` 를 `localStorage` 에 저장하는 코드를 넣으세요.
- 인정할 답이 여럿이면 `answers` 배열에 나열하면 됩니다. 예를 들어 14번은 곱셈과 나눗셈 순서가 다른 세 가지 표기를 모두 인정합니다.
- 보충 예제 2.4-3(정수·실수 나란히 선언)은 50번 한 문제로 합쳤습니다. 50문항 제한 때문입니다.
